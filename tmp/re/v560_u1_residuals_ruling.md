## 2. 根拠

### 2.1 ⒜ 第 6 引数 = フィット基準

呼出側（`0x66F2BE`〜`0x66F2D1`）の push 順は `a7=0, a6=1, a5=0, a4=0, a3=1, a2=1, a1=[0xB030A4]`。つまり第 6 引数 = `1`。

転送（`0x410C05`〜`0x410C29` の実読）:
```
FUN_00410A70(movie, a1=path, a2, a3, a4, a5, a6)
  ├─ FUN_004104C0(movie, a2, a3, a5, a6)     ; 0x410A90–0x410AA9  → param_5 = a6
  └─ FUN_004106C0(movie, a2, a4)             ; 0x410ABC–0x410AC9
```
`FUN_004104C0`（`docs/Oblivion_decompiled.c` L9316-9325）:
```
if (param_5 == 0) { iVar9 = movie->height; iVar2 = DAT_00b06c50 /*480*/; }
else              { iVar9 = movie->width;  iVar2 = DAT_00b06c4c /*640*/; }
fVar3 = (float)iVar2 / (float)iVar9;          // スケール
```
さらに `param_5 != 0` のとき x オフセット `param_1[6] = 0`、y オフセット `param_1[7] = 0.5 * (480 - height*scale)`。

→ **第 6 引数は「フィット基準（0=高さ 480 / 非 0=幅 640）」**。Intro は `1` なので幅基準。
（`0xB06C4C`=640 / `0xB06C50`=480 は実測済みの論理画面サイズ定数。）

### 2.2 ⒝ 入力の扱い `FUN_00410390(0x410390)`

```
410390  PeekMessageA(…, PM_REMOVE) → TranslateMessage → DispatchMessageA のループ（OS メッセージを空にする）
4103E3  inputDev = [[0xB3F928]+0x280]; inputDev->vtable[+0x0C]()   ; 入力デバイス更新（負なら中断）

            → return 0                                              ; 前景ムービー中に MessageMenu が出たら中断

        }

```

要点:
* **メニューやキー入力で「止まる」のではなく、ムービー自身がポンプを回して処理する**。
* skip を立てるのは**キー 5 / 0x1D が押されている**とき（MoviePlayer スレッドが生きている場合のみ）。
* 前景ムービー（`movie+0x20 != 2`）は `MessageMenu`(0x3E9) が開くと中断する＝**メッセージボックス系 UI だけが動画を止められる**。背景ムービー（mode 2）はこの条件の対象外。

（`docs/RE_EXE_REPORT.md` §21.3 の記載と一致。`0xB030A4` は v557 で GMST `sOblivionIntro` の値フィールドと確定済み。）

## 3. 移植への示唆

1. 導入ムービーは **RaceSexMenu を生成した後**に再生する（移植は「NEW 確定 → 直接 chargen 表示」なので、ムービーを挟むなら生成→再生→表示の順）。
2. ムービー中の入力は「塞ぐ」のではなく「skip キーだけ拾う」。移植でブロックするなら原版より強く閉じている。
3. フィットは**幅基準（640 論理幅）**。720p 素材なら 640x360＋上下 60 のレターボックス。
