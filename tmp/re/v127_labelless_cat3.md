## (2) 誤検出率の見積もり

### 2-1 構造的根拠（なぜ境界は「本体外」を意味するか）

Cat-3 採用には **CC パッド + well-formed terminator**（seed A）か **terminator 直後隣接**（seed B）が必須。Ghidra の逆アスは ret/jmp の後の int3 ランで停止するため、**直前に CC ランがある位置は定義上どの前台帳関数の本体にも含まれない**（＝ヘッダ無 = デコンパイル無）。これは V87 の「interior 4 件」とは独立した強い構造証拠で、残る interior は前台帳が 12–13B のジャンク/微型関数である場合の距離閾値起因（4 件すべて除外済み）。

### 2-2 指定された重複指標

| 指標 | 件数 | 評価 |
|---|---:|---|
| **named-header 767 件との重複** | **748**（着地率 97.5%） | **dec_index（FUN のみ）で第3カテゴリ判定をすると 748 件が「ヘッダ無し」と誤判定**される。本規則は全ヘッダ 21,232 を使うため 0 件。 |
| 台帳のみ（Cat-3b）との重複 | 339 | dec_index-only では同じく誤検出。本規則で除外。 |
| **int3 領域への着地** | 16 | accept が int3/invalid 先頭で棄却。 |
| FUN ヘッダ着地 | 20,124 | 設計上除外（Cat-1）。 |
| interior（前台帳から <16B） | 27 | うち V86 由来 4 = V87 interior と同一。 |
| 偽境界（terminator 誤一致） | 43 | V86 C 節由来。term_kind で全件除外（2-1 の精密化）。 |

**素朴規則（dec_index のみ、フィルタなし）に対する誤検出 = 748 + 339 = 1,087 件**（素朴出力 11,348 件に対し 9.6%）。本規則ではこれらを構造的に 0 にしている。

### 2-3 サンプル本文照合（Cat-3 の「decompiled 無」主張に対する直接検証）

- **Cat-3 から無作為に 30 件**（seed=20261026）を抽出し、直近ヘッダ関数の decompiled 本文と、エントリ直後 64B の命令オペランド（アドレス範囲の即値/disp）を照合。**一致 3/30**。
- 3 件を個別精査: ①0x981E0B / ②0x749FE0 は**直近ヘッダ自身のアドレス（0x981DDC / 0x749EE0）をオペランドに持つ**（＝むしろ独立関数が encloser を参照している構造）、③0x6A4560 は共有グローバル 0xB30AAC の一致。**いずれも本文包含の証拠ではなく見かけ一致 → 実質 0/30**。
- **positive control**: 台帳関数の体内点（関数先頭 +0x30）20 件で同じ照合 → 8/20 一致（ヒューリスティックの感度 40%。低感度なので 0/30 は「包含なし」の十分な証拠になる）。
- **誤検出率の結論**: 第3カテゴリ主張（「decompiled 無」）に対する誤検出は **点推定 0%（0/30）、95% 信頼上限 ≈ 10%（rule of three）**。付加的に、参照証拠あり（E8/E9 346 + imm32 9,808 = 98.96%）が「本物のコード＝関数候補」性を、無参照 107 件（1.04%）が最大の残余リスクを示す。
- 補足: raw union からの除外率 73.3%（28,114/38,375）は「誤検出」ではなく設計上の除外（既知ヘッダ 20,872 を含む）である点に注意。

## (3) gap 内複数ブロックの独立性判定（I1–I10 全 10 件）

### 3-1 手法（v96 残点 2 の解消 = 「CC-pad 規則は gap 先頭 1 点しか可視化しない」問題）

1. **全ブロック列挙**: v96 の `chain()`（線形デコードを ret/jmp で分割、CC/90/00 パッドをスキップ）を**逐語再実装** → ブロック数 **10/10 一致**（I1=140 / I2=30 / I3=1 / I4=9 / I5=1 / I6=1 / I7=2 / I8=2 / I9=2 / I10=4）。
2. **外部 E8/E9 参照**: gap 外のサイト → gap 内ターゲットを全 .text から走査。あわせて raw スキャン由来の外部 EB/条件 jcc も**線形逆アスで命令境界検証**（enclosing 関数先頭からデコードして site が命令先頭か）。
3. **到達性**: 各ブロックを capstone でデコードし内部 jmp/jcc/call 辺を抽出、gap 先頭から BFS。**間接 `jmp [reg*4+表]` はテーブルを実読みして辺に加算**。
4. **imm32 参照**: 各ブロック先頭への絶対ポインタ参照数（参照先 VA の実位置も特定しテーブル性を確認）。
