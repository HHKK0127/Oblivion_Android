判定: `[確定]` / `[確定(命令)]` / `[部分確定]` / `[確定負]`

## 1. 結論

### 1.1 `FUN_004028D0` = 自作文字列クラスの Set（[確定(命令)]）

`4028D0(this, src, flag)`:
* レイアウト: `+0` = `char*` buffer／`+4` = **word** 長（NUL を含まない）／`+6` = **word** 容量
* 書き込みは容量超過時のみ再確保（grow）。上限 `0xFFFF`（word 長のため）
* 返り値は書き込み成功可否

`FUN_00488810(this, src)` は `FUN_004028D0(this, src, 0)` を呼ぶだけのラッパ。

> **v555 の主張「`488810`→`4028D0` は配列への追加」は [確定負]。** 実体は文字列の代入。

### 1.2 `MapMenu+0xB0` は文字列オブジェクト（[確定(命令)]）

`MapMenu` の vtable `+0x0C`（`0x5BB880`）は `588C10(tile, 0xFB2)` で **`user4` のポインタ値**を取り、`488810` → `4028D0` で文字列へ書き込む。`0xFB2` = `user4` は §v557 の trait 表（`0x58ACC5` `push 0xFB2; push "user4"`）で確定。

> **v555 の主張「`MapMenu+0xB0` も `NiNode` と同型の `NiTArray`」は [確定負]。** `+0xB0` は文字列クラスの buffer フィールドであり、配列ではない（たまたま同じオフセットに別型が載っている）。

### 1.3 真の配列は `NiNode+0xAC` の埋め込み `NiTArray<NiPointer<NiAVObject>>`（[確定(命令)]）

| 項目 | 実測値 |
|---|---|
| vtable | `0xA43850` |
| base | `+0xB0`（= `NiNode+0xB0`） |
| max | `+0xB4`（word） |
| size | `+0xB6`（word） |
| growBy | `+0xBA`（word） |
| ctor | `0x4B2D30` |
| GetAt | `0x6D7F60` / `0x405790` |

`NiNode+0xAC` が配列オブジェクトの先頭（vtable）で、`+0xB0/+0xB4/+0xB6/+0xBA` がそのフィールド。

### 1.4 挿入経路の整理（[確定(命令)]）

| 関数 | 役割 |
|---|---|
| `0x589640` | **InsertBefore**（ソート済みリストの「初めて key を超えたノードの直前」へ） |
| `0x5B1E20` | **Append**（末尾追加） |
| `0x6AA320` | **Prepend**（先頭挿入・属性名バケット用／v552） |

→ v555 が「`488810`→`4028D0` も配列追加」としたのは挿入関数 3 種の取り違え。

### 1.5 `0x5B7550`（MapMenu の更新）（[確定(命令)]）

`size`（`+0xB6`）回ループし、各要素に `0x70B120` を適用して **AppCulled を解除**する。

### 1.6 `FUN_004057B0` = `Map@NiTexturingProperty` の遅延生成＋テクスチャ差し替え（[確定(命令)]）

* vtable `0xA7DBB4`（RTTI `.?AVMap@NiTexturingProperty@@`）
* ctor `0x704100`。`[+0x20]` のリスト先頭が空なら `push 0x10; call 0x401F00` → `704100` → `42BB90`（`NiTArray::SetAt`）
* `589D60`（image 要素の更新）がこれを呼び、`[Tile+0x2C]` に `0x20` を OR（テクスチャ更新要求フラグ）

### 1.7 `[Tile+0x2C]` フラグの実測

`589D60` が `or dword [this+0x2C], 0x20`。消費側は v557 の範囲外（残点）。
