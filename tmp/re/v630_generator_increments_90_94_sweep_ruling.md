## 1. generator 件数と増分 [確定(命令)]

| 関数 | 件数 | 役割（推定） | 増分 |
|---|---|---|---|
| `0x5C4340` | **21** | pane | +1 |
| `0x5C93F0` | **90** | **slider** | **+2** |
| `0x5C4480` | **22** | button（推定） | +1 |
| `0x5C4630` | **5** | toggle（推定） | +1 |
| `0x5C4800` | **1** | text（推定） | +1 |
| **合計** | **139** | | |

- 検算: `21×1 + 90×2 + 22×1 + 5×1 + 1×1 = 229`、`200 + 229 = 429`（final counter と一致）。
- 隣接 pane の id 差 = `1 + Σ(間の generator 増分)`。偶数差（4, 10）は間の +1 群の寄与で、
  **「item +2」という一般化が誤り**だったことの帰結（数値自体は正）。
- **139 = 21+90+22+5+1 が generator 関数別の件数と 1:1 対応**（査読 §5 の確認）。

## 2. `0x5C93F0` = slider [部分確定]

- 90 回 = **Slider 90**（chargen のスライダ数と一致）。
- `push imm 0..0x36`（最大 54）は slider の**型/テンプレート番号**であって **id ではない**。**id は counter 側**（§5）。

## 3. `+0x90` / `+0x94` の掃引 [部分確定]

- **`0x5C4340` 内**の `+0x90`/`+0x94` 参照は **1 箇所のみ**: `0x5C4444 mov [ebx+edx*4+0x94], esi`（edx=arg4）。
- **全 .text の `[reg + idx*4 + 0x94]` store は 6 箇所**、**すべて RaceSexMenu builder 内**:
  `0x5C4444` / `0x5C45EE` / `0x5C47C9` / `0x5C48E1` / `0x5C9584` / `0x5C958B`。
- `[reg + idx*4 + 0x90]` は 5 箇所（`0x773192`/`0x77320C`/`0x7BF062`/`0x7BF097`/`0x812177`、いずれも別モジュール）。
- **含意**: `+0x94` は indexed write される → **`arg4 == -1` なら配列は永遠に書かれない**（査読 §3 の指摘どおり両立しない）。
  → 読み（推定）: **`+0x90` = pane cache（arg4=-1 のときの格納先）**、**`+0x94` = item id→tile 配列（item builder が非負 id で書く）**。
- → **V-630-1 [未確定]**: arg4 の値（pane ごとに変わるか）と 6 store 各々の index 源。

## 4. `Character+0xE8` の writer [部分確定]

- `[reg+0xE8]` への store は 13 箇所、**`mov [reg+0xE8], -1` は存在しない**（`0x5DDC7E mov [ecx+0xe8],0` は 0 であって -1 ではない）。
- → **静的に -1 を確定できない**。**V-629-1 は runtime のまま**（査読 §4 のとおり）。

## 5. `0x5C4340` の +1 の意味 [確定(命令)]

- pane 生成の**副作用で counter を 1 進める**（`0x5C438A..0x5C4392`）。arg4==-1 のとき **id = counter 値**。
- すなわち +1 は「**スロット消費**」であり、id 採番そのものではない（id は counter の値を読む）。
