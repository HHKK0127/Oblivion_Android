## 2. `0x587B20` の実体 [確定(否定側)＋positive 情報]

```
0x587B20(a1?, a2:byte)   [ret 0 → cdecl]
  cmp byte [esp+0x18](a2), 0        ; a2 == 0 → 0x587B9C（そのまま [0xB3A708] を返す）
  eax = [0xB3A708]
  if ([0xB3A708] != 0) → 0x587B9C    ; 既に初期化済みなら何もしない
  esi = malloc(1)
  0x4E4A10([0xB13970], 0x33)         ; id 0x33(51) の配列 grow（v547: 0x4E4A10=動的配列 grow/set）
  [0xB3A708] = esi
  0x4E4A10([0xB13970], 0x33)         ; 2回目（second touch）
  return [0xB3A708]
```

* **`0x4E4A10` は memory 998件に記録済み**（callers_of(0x4E4A10)=1043＝v546 済み・`ret 4` の grow/set）→ **本裁定はその呼出を `0x587B20` 内で初めて特定**。
* **`[0xB13970]`** は v574 で「`0x42BB90([0xB13970], id-0x3E9, …)`＝生成済み配列登録」と同一オブジェクト → **open 前処理が id-0x3E9 配列のキャパシティを先に確保する**構造 [確定(命令)]。
* **`[0xB3A708]`** は v547 の「型索引 0x33 manager スロット・同一 .data 窓」記述と接続（V-548-2 の一部裏付け）。
