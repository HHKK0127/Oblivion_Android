## claims.md の座標との対応（座標系が違う。片方を捨てない）

`docs/claims.md` の Panel レーン残項目は **Eyes(122,379)**・**Race(250,215)** と書く。
実測は **Eyes(377,472)**・**Race(377,219)**。これは**座標系の違い**なので、変換式つきで
両方残す（「古い」と切り捨てない）。

**変換式**（`race_sex_panel.cpp` の実装そのもの）:

```
s = min(screenW / 1280, screenH / 960)
panelOrigin = ( (screenW - 1280*s)/2 + 100*s ,  (screenH - 960*s)/2 + 195*s )
device = panelOrigin + canvas * s
row(canvas_y) = floor((canvas_y - 195) / 93)      # 93 = ROW_HEIGHT
```

**現行レイアウトでの対応**（surface 1280x870 → s=0.90625、panelOrigin=(150.625, 176.719)）:

| 表記 | canvas | device | どの行に当たるか |
|---|---|---|---|
| 実測（本記録） | (250, 325.5) | **(377, 472)** | row 3 = Eyes（中心） |
| 実測（本記録） | (250, 46.5) | **(377, 219)** | row 0 = Race（中心） |
| claims | (122, 379) | (261, 520) | **row 1 = Face**（Eyes ではない） |
| claims（device と解釈） | — | (122, 379) | x=122 < 150.6 で **pane 外＝ミス** |
| claims の Race(250,215) | (109.7, 42.2) | (250, 215) | row 0 = Race（**device と解釈すれば一致**） |

**特定できた基準**: claims の (122,379) は **canvas 原点 y=100・s=1.0**（surface 1280x960）で
**row 3（Eyes）に当たる**（`floor((379-100)/93) = 3`、x=122 は pane 内）。現行の
`PANEL_CANVAS_Y = 195`（`race_sex_panel.h:317`、背景を縦センタリングした値）とは
**y が 95 違う**。つまり claims の座標は **spec §9.5b（描画レイアウト）で原点を 195 に
する前**のもので、現在は同じ座標を押しても Eyes に当たらない。

**結論**: 両方を残す。claims の (122,379) は「原点 y=100 時代の正しい値」であり、
現行の正しい値は (377,472)（canvas (250,325.5) の device 変換）。`#198`（.ai-todo の
ページ id 表のずれ）と同じく**突き合わせ対象**だが、**捨てる対象ではない**。
